# Stage 208 Fix 2 — تسلسل مستقل لرقم الطلب لكل متجر

تم تعديل منطق رقم الطلب على مستوى قاعدة البيانات حتى لا تشترك جميع المتاجر بنفس التسلسل.

## السلوك الجديد
- كل متجر يبدأ بتسلسله الخاص: 1، 2، 3 ...
- مثال: قلب المدينة يمكن أن يكون طلبه #5، وبقالة بهاء يمكن أن يكون طلبها #5 في نفس الوقت بدون تعارض.
- رقم الطلب الظاهر في تطبيق المتجر، الإيصال، إشعارات الطلب والسائق يبقى `order_number` نفسه، لذلك لا نحتاج تبديل واجهات التطبيق إلى حقل جديد.
- المعرّف الحقيقي للطلب `orders.id` (UUID) يبقى فريدًا عالميًا ويستخدم داخليًا.
- الطلبات القديمة يعاد ترتيب أرقامها لكل متجر حسب تاريخ الإنشاء من الأقدم إلى الأحدث.
- التوليد الجديد يتم داخل Supabase بعملية آمنة للتزامن، حتى لو وصل طلبان بنفس اللحظة لنفس المتجر.

## خطوة مطلوبة مرة واحدة في Supabase
شغّل الملف التالي في SQL Editor:

`supabase/stage_208_fix2_per_store_order_number.sql`

بعد تشغيله لا يحتاج العميل لإرسال رقم الطلب؛ قاعدة البيانات تعطي الرقم تلقائيًا حسب المتجر.

## ملاحظة
هذا التعديل لا يغيّر منطق قبول الطلب، الطباعة، السائق، الشفتات، الأقسام أو المنتجات. هو فقط يغيّر طريقة توليد `order_number` من تسلسل عالمي إلى تسلسل مستقل لكل متجر.
