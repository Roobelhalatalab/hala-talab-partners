# Stage 208 Fix 3 — عزل بيانات وإعدادات كل متجر

تمت مراجعة نقاط البيانات الخاصة بالمتجر في تطبيق الشركاء للتأكد من أن كل متجر يعمل ضمن بياناته فقط.

## ما تمت مراجعته
- الطلبات وتفاصيل الطلب: مرتبطة بـ `store_id` للمتجر الحالي.
- تسلسل الطلبات: مستقل لكل متجر (Fix 2).
- التقارير والمبيعات: الاستعلامات مفلترة بـ `store_id`، وملخص المبيعات RPC يحدد المتجر من `auth.uid()`.
- المنتجات والأقسام والإضافات والشفتات: مرتبطة بمتجر الحساب الحالي، مع RLS على جداول الربط.
- العروض والكوبونات: جميع عمليات القراءة/التعديل/الحذف مرتبطة بـ `store_id`.
- التقييمات: مرتبطة بـ `store_id`.
- الإشعارات: القراءة والحذف والتحديث أصبحت تتحقق صراحة من `store_id` إضافة إلى RLS.
- أدوات العملاء/الأداء/السائقين الخاصة بالمتجر: الطلبات مفلترة بـ `store_id`.
- رسائل الدعم: صندوق دعم المتجر أصبح مفلترًا أيضًا بـ `store_id` بدل الاعتماد على user_id فقط.
- إعدادات الطابعة: أصبحت محفوظة لكل حساب متجر على الجهاز بدل مفتاح مشترك بين جميع المتاجر. يوجد ترحيل تلقائي مرة واحدة من إعدادات Stage 208 القديمة حتى لا تضيع إعدادات المتجر الحالي.

## ملاحظات بنيوية
قاعدة البيانات تفرض متجرًا واحدًا لكل owner عبر unique owner_id، لذلك ربط الإعدادات المحلية بمعرف الحساب يعزلها فعليًا لكل متجر.

لم يتم تغيير منطق السائق أو الشفتات أو المنتجات أو الطباعة نفسها خارج حدود العزل المذكورة.
