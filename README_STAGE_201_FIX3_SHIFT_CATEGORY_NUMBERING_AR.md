# هلا طلب – الشركاء – Stage 201 FIX3

هذا الإصلاح يخص ترقيم وترتيب أقسام المتجر عند استخدام شفتين.

## ما تم إصلاحه
- الترقيم الظاهر للأقسام أصبح مستقلاً لكل شفت ويبدأ دائمًا من 1 حتى عدد أقسام ذلك الشفت.
- لا تظهر أرقام مكررة أو قفزات مثل 1،2،3،6،9 بسبب القيم التاريخية في قاعدة البيانات.
- البحث لا يغيّر رقم ترتيب القسم الأصلي داخل الشفت.
- حقل "ترتيب القسم" عند التعديل يعرض الموضع الفعلي داخل الشفت، وليس رقم sort_order التاريخي.
- إضافة قسم جديد تقترح الموضع التالي داخل نفس الشفت فقط.
- بعد حفظ/تغيير ترتيب قسم، يعاد جلب ترتيب السيرفر حتى تبقى واجهة المتجر متطابقة مع الترتيب الحقيقي.

## مهم
- لم يتم تغيير منطق ترتيب المنتجات داخل الأقسام.
- لم يتم تغيير RPC ترتيب الأقسام في Supabase؛ Stage 200 أصلًا يرتب الأقسام ضمن الشفت نفسه.
- لا يوجد SQL جديد لهذا الإصلاح.
- لم يتم تعديل ملفات Android signing ضمن هذا الإصلاح.
