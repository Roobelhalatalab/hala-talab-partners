# هلا طلب – الشركاء – Stage 200

هذه المرحلة تكمل فصل قوائم المطعم حسب الشفت بدون تغيير المتاجر ذات الشفت الواحد.

## ما تغير
- إزالة خيار «الكل» من شريط أقسام إدارة المنتجات؛ يتم اختيار قسم محدد دائمًا.
- عرض الأقسام كبطاقات صغيرة تحتوي اسم القسم وصورته.
- عند وجود شفتين تظهر تبويبات الشفت الصباحي والمسائي، ولكل شفت أقسامه المستقلة.
- يسمح بنفس اسم القسم في شفت مختلف، مثل «مشويات» صباحي و«مشويات» مسائي.
- المنتج يرتبط بمعرّف القسم `category_id` وليس باسم القسم فقط، لمنع خلط الأقسام المتشابهة.
- ترتيب المنتجات صار مستقلًا لكل قسم فعلي.
- المتاجر ذات شفت واحد تبقى على السلوك الحالي.
- تم الحفاظ على `category_name` للتوافق مع الأجزاء القديمة، ويجري مزامنته تلقائيًا من القسم الحقيقي.
- ملفات توقيع Android الأصلية باقية كما هي.

## خطوة Supabase المطلوبة
شغّل مرة واحدة فقط:

`supabase/stage_200_shift_scoped_categories.sql`

ثم شغّل التطبيق وجرب متجرًا بشفتين:
1. افتح الشفت الصباحي وأنشئ قسم «مشويات».
2. افتح الشفت المسائي وأنشئ قسم «مشويات» أيضًا.
3. أضف وجبة مختلفة داخل كل قسم.
4. تأكد أن كل شفت يعرض أقسامه ووجباته منفصلة.

## ملاحظة
تطبيق العميل والمنيو الإلكتروني يحتاجان المرحلة التالية لقراءة `category_id` وفصل الأقسام ذات الاسم المتشابه بشكل كامل. لا يلزم تعديلهما قبل نجاح اختبار تطبيق المتجر.
